# 魔法學系統總覽｜65-cpp.26

## 核心定位

魔法學與儀式學分離。魔法學以七元素、技能樹與魔法學點數為核心；實際可施放魔法會連結既有技能模板，因此直接共用多段攻擊、事件 Trigger/Condition/Effect/Status 與場地效果核心。

## 七元素

固定元素：`暗 / 光 / 金 / 木 / 水 / 火 / 土`。

每位角色各自保存：
- 元素目前儲存量 `element_storage`
- 元素基礎／最終儲存上限
- 元素親和 `element_affinity`
- 元素抗性 `element_resistance`
- 元素弱點 `element_weakness`

元素儲存上限預設可為 0，技能、魔法、儀式與道具可透過既有元素上限加成機制提高。

## 魔法技能樹

每個 `magic_studies` 節點可設定：
- 名稱、分類、品階、說明
- 所屬元素
- 魔法學點數成本
- 前置節點 `prerequisite_ids`
- 技能樹座標／圖示／分支樣式
- 七元素施放成本 `element_cost`
- 連結技能模板 `linked_skill_template_id`
- 必要魔法書 `required_book_item`
- 學習時是否消耗魔法書 `consume_book`

角色點亮節點時，C++ 後端驗證前置節點、魔法學點數與魔法書，不依賴前端判斷。

## 魔法施放

已學節點若連結技能模板，可由：

`POST /api/magic-studies/{id}/cast`

直接施放。後端流程：
1. 驗證角色已學會節點。
2. 驗證連結技能模板仍存在。
3. 驗證七元素儲存量足夠。
4. 將節點元素注入技能資料。
5. 戰鬥中共用既有 C++ 多段／事件技能核心執行。
6. 成功後扣除元素儲存量。

## 元素傷害

元素傷害倍率：

`100% + 攻擊者對該元素親和 - 目標對該元素抗性 + 目標對該元素弱點`

最終倍率限制為 `0% ~ 1000%`。

玩家、怪物與 NPC 都可參與此計算；怪物／NPC 的抗性與弱點在 DM 編輯器中收進進階折疊區，避免一般介面過度複雜。

## 魔法書

魔法節點可指定必要魔法書名稱：
- 未持有時不能學習。
- `consume_book=false`：只驗證持有。
- `consume_book=true`：學會後消耗一本。

## 魔法學點數

沿用角色 `magic_points`：
- 學習魔法節點時消耗。
- 可由任務、道具或 DM 既有管理機制發放。
- 不作為施放成本；施放成本使用七元素儲存量。
