# 任務行動系統總覽｜73-cpp.34.22

本版把任務從單一文字要求擴充為 `task_steps` 結構化環節。每位玩家的進度保存在 `task_participants.progress`，房間內的任務行動由 C++ 驗證。

## 支援環節

- `cooperative_seal`：要求指定 NPC 在同一房間／同一地點，可再指定怪物模板；完成後可把該房間怪物標記為 `sealed`。
- `place_anchor`：在目前地圖節點建立持久化任務錨點，可要求不同節點、指定錨點數量與名稱。
- `reach_location`：到達指定名稱的地圖節點後才能推進。
- `interact_npc` / `escort_npc`：驗證指定 NPC 是否存在、是否可互動、是否與玩家同地點。
- `perform_ritual`：驗證玩家是否學會指定儀式，且該房間已有完成的對應儀式實例。
- `defeat_target`：驗證指定怪物在房間內已被擊敗、死亡或封印。
- `collect`：驗證角色背包中指定物品數量。
- `investigate` / `custom`：可作為一般調查或 DM 自訂步驟。

## 例：與 NPC 一起封印詭異

任務步驟可指定 NPC、怪物、地點與「必須同一地點」。玩家必須先移動到同一節點，NPC 與詭異也必須在可作用範圍內，才能按下封印進度。最後一段完成時可自動把詭異標記為 `sealed`。

## 例：安插錨點

DM 可設定需要 3 個「穩定錨點」，並開啟「錨點不可重複地點」。玩家每到一個不同地圖節點即可執行一次安插；錨點保存在 `room_task_anchors`，地圖節點會顯示 ⚓ 數量。

## DM 控制

DM 任務面板提供「調整環節」，可以校正每位玩家的步驟進度。若尚有環節未完成，正常的「完成並發獎勵」會被 C++ 阻止；DM 可明確選擇強制完成。
